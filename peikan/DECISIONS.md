## 2026-10-20 · 目录名改为 peikan

**决定**：`ophelia-bili/` → `peikan/`

**为什么**：manifest id 早就是 `peikan`，但目录名一直是 `ophelia-bili`。官方校验器第一条就报
`INVALID_MANIFEST: id "peikan" does not match its directory name`，生产加载器会拒装。

**之前是怎么绕的**：靠 `_stage/peikan` 打包——stage 目录名对，所以装得上。绕了一整天。

**代价**：141 个一次性补丁脚本里写死的路径全部失效。这些脚本本来就该删（见下）。

**没做的事**：没有在改名时同步更新那些补丁脚本。它们是一次性产物。

## 2026-10-20 · 三个「节制」缺口补齐

对照源仓库 `dsh-bili-whale` 的 24 个命令，查出三处它写死、我没做的限制。

### ① 风控熔断（新 `lib/risk.js`）

**源仓库的原话**：
> 12015: 需要评论验证码（说明被风控盯上了，停手）
> 否则 agent 会把「被风控拒了」当成「发成功了」，绕过了「撞风控立刻停手」的红线

**我的问题**：只判 `code === 0`。被限流当成普通失败，下一轮接着撞。撞多了号会废。

**决定**：三种状态

| 级 | 触发 | 行为 |
|---|---|---|
| cooldown | 412 / -352 / -412 | 冷却数小时，期间所有写通道拒绝 |
| manual | 12015 / 12016 / -101 | 冷却 24h，**过期也不自愈**，要人处理 |
| ignore | 65004 / 65006 / -404 / -400 | 不拉闸（正常业务结果） |

**接入点**：publish / dynamic / social / likes / retract 五个通道，各自 `check` 进闸 + `record` 撞闸。

**为什么分 manual**：验证码只能人去点。自动恢复等于假装没事，下一轮继续撞。

### ② 同一视频 7 天冷却

**源仓库**：`同一视频 7 天内一次`

**我的问题**：`share-state.json` 整个按天重置，跨天就忘了。只有「今天推过」这一层。

**决定**：状态里加 `recent: [{bv, at}]`，**跨天保留**，90 天滚动裁剪。默认 `sameVideoDays: 7`。

**为什么不是永久**：永久不重复会让好视频永远推不出去（她可能三天后才发现它值得推）。7 天是源仓库验证过的窗口。

### ③ 同一人 30 天只回一次

**源仓库**：`同一个人（可选）30 天只回一次`

**我的问题**：完全没有。同一个人追着聊，一天能回十次。

**决定**：`canReply` 加第 ④b 道。默认 `sameSomeoneDays: 30`。

**主人豁免**：`ownerMid` 不受这条限制——但主人由 kill switch 和配额管，不是没人管。

**为什么这条重要**：这是「人际上的分寸」，不是技术限制。追着一个人说话会让人不适。

## 2026-10-20 · 分享补上沉默衰减和内容闸门

**问题**：`silence` 只接在 `bili_publish` 上，自动分享那条路完全不看。
主人沉默七天、额度归零了，她还在推。

**又是同一个毛病**：一个行为两个出口，只改了一个。今天第三次。

**决定**：判定逻辑放进 `shareNote` 内部（唯一出口），`wake` / `bili_share` 都传 `cfg`。

**踩的坑**：修完之后四处调用点都没传 `cfg`，修了等于没修。差点漏掉。

## 2026-10-20 · 笔记元数据不再让模型传

**问题**：`bili_note` 的 `noteHints` 明明在 `debrief` 返回里，她写了 4 条笔记**一次都没传** cover/duration。

**判断**：让模型「记得复制字段」和让人「记得填表格」，失败方式一模一样。不可靠。

**决定**：`store.addNote` 成为唯一补全点，从 `video-meta.json` 缓存自动补。模型传了就以模型为准。

**更深的教训**：机械性的活该由代码做，不该要求模型凭记性完成。

## 2026-10-20 · 人格读助手自己的两个文件

**决定**：`resolvePersona` 优先读 `agents/<id>/identity.md` + `AGENTS.md`，读不到才退回本地 `persona.md`。

**为什么两份都要**：用户说过一句关键的话——
> 这只是我的提示词，不代表别的用户的提示词也是这样

我原本判断「AGENTS.md 里全是 PowerShell 纪律，与 B站 无关，不该拼」。
**那个判断只对当前这台机器成立。** 别的用户可能在 AGENTS.md 里写「你是我女朋友」「别聊政治」。那是人格的一部分。

**教训**：拿一个样本推全体，是今天犯得最多的错。

## 2026-10-20 · 日记还给她

**问题**：日记是程序拼的模板字符串：

```
## 时间戳
醒来 19:16。看了 5 条（偏好滤掉 0），深读 2 条。
最值得的一条：《xxx》 13/20。
```

每节一模一样。**这不是日记，是日志。**

**决定**：新增 `bili_diary` 工具，她自己在循环里写。标题、内容、写几段都是她的。

**规则模式**：那条路没有模型参与，所以保留自动记录，但标题明确标「规则模式自动记录」——不冒充她的笔迹。

**日志归 audit.jsonl**，不占日记的地方。

## 2026-10-20 · 有未回消息就不分享

**问题**：主人在私信里回了她，她直接去看视频并分享了，一句没回。

**原来的做法**：prompt 里写「建议流程（不必严格照做，你有判断权）：1) 先调 bili_inbox…」
**三重退路**——建议、不必照做、你有判断权。她当然跳过。

**决定**：代码门。查未回私信 + 未回评论，`pendingCount > 0` 就不分享。

**为什么写进代码而不是 prompt**：prompt 里的「建议」等于把责任推给模型的自由发挥。
自由是给她「看什么」的，不是给她「先不看人」的。
